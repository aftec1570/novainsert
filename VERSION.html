1.3.0 – 2026-11-14

Feature release. Projects, presets (devices.json), calibrations and settings from 1.0.x to 1.2.1 load unchanged on every platform; a stored calibration stays valid at the rate it was measured at.

  • New: 44.1, 48, 88.2, 96 and 192 kHz. NovaInsert used to run at 48 kHz only. Every timing inside it (meters, fades, the level CAL tone and window, the delay-compensation checks, the millisecond readouts) now follows the device rate. Other rates (176.4, 32 kHz, ...) still show "Unsupported rate".
  • New: changing the sample rate re-measures every loop on its own ("Sample rate changed"). Change the rate only while the transport is stopped, never during playback or recording. A calibration is stored per rate, so going back to a rate reuses it.
  • New: no limit on active instances. Up to 20 could run at once before; a 21st silently got no loop. More than 20 are allowed now; 20 is what we have stress-tested, so beyond that the CPU at very small buffers is the limit.
  • Fixed: a stereo unit whose channels sit half a sample apart failed with "Channel asymmetry" now and then. Two channels whose loops lie within half a sample are one loop and lock on the same delay; a real L/R skew of a sample or more still fails. (BUGS.md #7)
  • Changed: "Unvalidated host version" appears only for REAPER older than 7.6. It is a notice, not an error. (#8)
  • Validation: macOS hardware-validated on the UA Apollo bench at all five rates (four direct analog loops measure, lock and render sample-aligned at each; ADAT loops at 44.1 and 48 kHz) and on REAPER 7.86; the live rate change was proven with the transport stopped. Windows (RME Babyface Pro, native ASIO) and Linux: the new rates and the instance limit are covered by the unit tests, not yet by hardware runs; Linux stays beta.

1.2.1 – 2026-11-12

Bug-fix release for the first Windows reports. Projects, presets (devices.json) and settings from 1.0.x, 1.1.x and 1.2.0 load unchanged on every platform.

  • Fixed: "Audio device lost" although the interface works (all platforms; reported on Windows). When REAPER reports more channels than it hands out audio for, NovaInsert no longer treats the device as lost. A preset whose own channel gets no audio now says so and names the channel; enable it in Preferences > Audio > Device.
  • Fixed: the meter view and unit are remembered. VU / TUBE / LED / TWIN and dBu / dBFS are stored in settings.json and kept when REAPER restarts.
  • Windows: ASIO4ALL and FlexASIO are refused. With these wrappers (or any non-ASIO driver) NovaInsert shows a warning and passes the audio through dry; use the interface's own ASIO driver.
  • Validation tiers unchanged: macOS hardware-validated (UA Apollo bench); Windows real hardware (RME Babyface Pro, native ASIO, cable loops); Linux functionally validated in a virtual environment, hardware timing validation pending (beta).

1.2.0 – 2026-11-10

Other ASIO interfaces and outboard have not been tested yet; reports are welcome.

1.1.1 – 2026-11-10

Bug-fix release for macOS and Linux. Projects, presets (devices.json) and settings from 1.0.x and 1.1.0 load unchanged.

  • Fixed: a latency measurement started while the transport plays could fail with "no return". This happened when a project with measure-on-open was opened during playback, or when an instance was inserted or re-measured while playing. The program that was still travelling round the hardware loop landed in the silence before the measuring click and confused the arrival detection. NovaInsert now holds the send silent and lets the loop drain (about 1.8 s) before it sends the click whenever the transport is playing. Measurements with the transport stopped are unchanged.
  • macOS: validation tier unchanged (hardware-validated on a UA Apollo bench). Linux: functionally validated in a virtual environment; hardware timing validation pending (beta).
  • Windows x64 (ASIO) is not in this release; it follows in a later release.

1.1.0 – 2026-11-09

Linux release. Projects, presets (devices.json) and settings from 1.0.x load unchanged on every platform.

  • New: Linux x86_64 build (NovaInsert-1.1.0-Linux-x86_64.tar.gz, glibc 2.35 or newer, ALSA). install.sh copies the plug-in to ~/.vst3. Validation: functionally validated in a virtual environment; hardware timing validation pending (beta).
  • New: audio-driver check. NovaInsert arms and measures only on REAPER's native driver: CoreAudio on macOS, ALSA on Linux. On any other driver (JACK, PulseAudio, Dummy Audio, …) it stays unarmed and shows "REAPER's audio driver is not supported. NovaInsert needs ASIO on Windows / ALSA on Linux".
  • macOS: unchanged features; validation tier unchanged (hardware-validated on a UA Apollo bench).
  • Windows x64 (ASIO) is not in this release; it follows in 1.1.1.

1.0.1 – 2026-11-08

Bug-fix release. Projects, presets (devices.json) and settings from 1.0.0 load unchanged.

  • Fixed: mouse-wheel direction on the trim knobs could be reversed (#1). Wheel up raises a trim, following the macOS scroll setting. A scroll utility that reverses only the mouse (Logi Options+, Mos, Scroll Reverser, LinearMouse…) leaves macOS's "natural scrolling" flag set, so the knobs turned backwards and no plug-in can detect that. New global option SETUP → Mouse wheel: Reverse turns them the other way.
  • Fixed: "Interface" in PRESET SETUP went back to Apollo when saving a Custom preset (#2). The hardwired interface list (Apollo x, Apollo Twin MkII, Custom) is gone. PRESET SETUP and SETUP now show the audio device as REAPER reports it; the dBu-at-0-dBFS values are entered directly (default +24.0 dBu), since REAPER does not report a converter's analog level.

1.0.0 – 2026-11-06

First public release: REAPER-only VST3 hardware insert for macOS (Apple silicon) with automatic, sample-accurate round-trip latency measurement, device presets, mono/stereo routing per direction, VU and bar meters, level calibration (SEND CAL / RETURN CAL), Insert and Effect modes and automatic realtime rendering.
